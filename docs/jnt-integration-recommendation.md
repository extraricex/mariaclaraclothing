# J&T / JET Integration Recommendation

## Summary

The documentation reviewed is for J&T Indonesia:

https://developer.jet.co.id/documentation/index#Order

Our website currently operates as a Philippine storefront:

- Customer addresses use Philippine provinces, cities, and barangays.
- Currency is PHP.
- Phone numbers are Philippine format.
- Orders use Cash on Delivery.

The reviewed J&T API expects Indonesia-specific fields:

- Indonesian phone format such as `+62...`
- Currency values in IDR.
- `origin_code`
- `destination_code`
- `receiver_area`
- J&T Indonesia dashboard credentials.

Because of this, we should not connect it live until we confirm whether the business will use J&T Indonesia or a J&T Philippines API account.

## What The Order API Does

The Order API creates a shipment order in J&T and returns a waybill number.

Basic flow:

1. Customer places an order on the website.
2. Admin confirms the order, usually after COD confirmation.
3. Our server sends the shipment request to J&T.
4. J&T returns an `awb_no`.
5. We save that AWB/tracking number on the order.
6. Admin can share the AWB with the customer.

## API Request Shape

The API uses:

- Method: `POST`
- Header: `application/x-www-form-urlencoded`
- Body fields:
  - `data_param`
  - `data_sign`

`data_param` is a JSON string:

```json
{
  "detail": [
    {
      "username": "from-dashboard",
      "api_key": "from-dashboard",
      "orderid": "MCC-ORDER-0001",
      "shipper_name": "Sender name",
      "shipper_contact": "Sender contact",
      "shipper_phone": "+628123456789",
      "shipper_addr": "Sender address",
      "origin_code": "JKT",
      "receiver_name": "Customer name",
      "receiver_phone": "+62812348888",
      "receiver_addr": "Customer address",
      "receiver_zip": "00000",
      "destination_code": "JKT",
      "receiver_area": "JKT001",
      "qty": 1,
      "weight": 1,
      "goodsdesc": "Clothing",
      "servicetype": 1,
      "insurance": "",
      "orderdate": "2026-06-05 15:30:00",
      "item_name": "Maria Clara Clothing",
      "cod": 120000,
      "sendstarttime": "2026-06-05 08:00:00",
      "sendendtime": "2026-06-05 18:00:00",
      "expresstype": "1",
      "goodsvalue": 120000
    }
  ]
}
```

`data_sign` is generated by:

```text
base64(md5(data_param + secret_key))
```

## Required Business Information

Before live integration, we need:

- Correct J&T country account.
- API endpoint URL.
- Username.
- API key.
- Secret/signature key.
- Shipper name.
- Shipper contact.
- Shipper phone.
- Shipper address.
- Origin city code.
- Service type:
  - `1` pickup
  - `6` drop off
- Express type:
  - `1` EZ / Regular
- Insurance agreement/rules.
- COD agreement/rules.

## Required Location Mapping

The API requires J&T area codes, not just readable addresses.

For Indonesia, the docs require:

- `origin_code`
- `destination_code`
- `receiver_area`

For our Philippine website, we currently store:

- Province
- City / Municipality
- Barangay
- Address line

Before live integration, we need a mapping table from our checkout address fields to J&T’s required destination/area codes.

Recommended future table:

```text
jnt_area_mappings
- country
- province_name
- city_name
- barangay_name
- destination_code
- receiver_area
- postal_code
- active
```

## Recommended Architecture

Do not call J&T from frontend JavaScript.

J&T credentials must stay server-side.

Recommended backend route:

```text
POST /api/admin/orders/:orderNumber/jnt/create-shipment
```

This route should:

1. Require admin authentication.
2. Load the order.
3. Validate required shipping/customer fields.
4. Convert our order into J&T payload format.
5. Generate `data_sign`.
6. Send request to J&T only when live mode is enabled.
7. Save the returned AWB/tracking number on the order.
8. Save API request status/error reason for admin visibility.

## Recommended Admin Workflow

In the order detail page:

1. Admin confirms COD.
2. Admin checks package/items.
3. Admin clicks `Create J&T shipment`.
4. If successful:
   - Save AWB number.
   - Set tracking number.
   - Mark delivery status as ready or shipped depending on workflow.
5. If failed:
   - Show the J&T error reason.
   - Keep the order editable.

## Recommended Implementation Phases

### Phase 1: Dry Run Preparation

Build the backend and admin UI without sending to J&T.

Includes:

- J&T settings placeholders.
- Payload builder.
- Signature generator.
- Validation.
- Admin button.
- Dry-run preview of the request payload.
- Tests.

This is safe because it does not require live credentials.

### Phase 2: Sandbox Integration

Once credentials and endpoint are available:

- Add environment variables.
- Enable sandbox mode.
- Send test orders.
- Store J&T sandbox responses.
- Validate area-code mapping.
- Confirm with J&T support that payloads are correct.

### Phase 3: Production Integration

Only after sandbox is approved:

- Enable production endpoint.
- Add production credentials.
- Add logging for failed shipment creation.
- Add retry handling.
- Add tracking status sync later.

## Risks

- The reviewed API is Indonesia-specific.
- Philippine address data will not work without J&T-compatible area codes.
- COD amount and currency differ between PHP and IDR.
- Incorrect signature generation will cause API rejection.
- Duplicate `orderid` values are rejected.
- Live shipment creation should not happen before COD confirmation.

## Recommendation

Start with Phase 1 only.

Build a dry-run J&T adapter that prepares our system for shipment creation, but does not send real API requests yet. After we confirm the correct J&T country/API account and receive credentials plus area-code mappings, we can safely enable sandbox/live integration.
